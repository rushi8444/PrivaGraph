1. EXECUTIVE SUMMARY & ELEVATOR PITCH
================================================================================
Q: What is this project and what problem does it solve?
A: 
PrivaGraph (Privacy-Guard) is a high-performance, privacy-preserving knowledge
graph middleware and security proxy that sits between enterprise proprietary
documents and third-party cloud Large Language Models (OpenAI GPT-4o, Anthropic
Claude, Google Gemini).

The Problem:
Enterprises want to leverage cloud LLMs for retrieval-augmented generation (RAG)
and natural language query answering, but they cannot legally or ethically send
confidential data containing Personally Identifiable Information (PII, such as
names, SSNs, phone numbers, emails, salaries, employee IDs, and internal project
codes) to external cloud AI providers. Standard redaction destroys relationships
and context, making the LLM unable to answer analytical questions. Furthermore,
standard naive chunking causes cross-contamination in tabular data, linking
unrelated personnel and salaries together.

The PrivaGraph Solution:
1. Multi-Format Ingestion: Supports both Open Knowledge Format (OKF) Markdown
   and native PDF documents via PyMuPDF, extracting clean text and tables.
2. Anti-Cartesian Table Isolation: Converts structured tables into strictly
   row-scoped sentences, preventing cross-row entity contamination and combinatorial
   graph explosion.
3. Zero Cloud PII Exposure: Real sensitive entities are detected locally and
   replaced with deterministic opaque tokens (e.g., "John Smith" -> "⟦E7_PERSON_001⟧").
4. Relationship Preservation: Because tokenization is deterministic via keyed HMAC,
   the system constructs an anonymized multi-document Knowledge Graph (NetworkX)
   linking tokens across different documents without ever exposing real identities.
5. AES-256-GCM Local Vault: The true mapping (token -> plaintext) is encrypted
   locally with authenticated 256-bit AES-GCM and stored inside a local secure vault.
6. Department Boundary & Multi-Hop Traversal: Queries are scoped with department
   boundaries (preventing leaks across divisions) and traverse multi-hop reporting lines.
7. OWASP Sanitization: Subgraphs retrieved for a user query are scoped with department
   boundaries and scanned for prompt injection before being sent.
8. Query-Aware Local Answer Synthesis: When cloud models return tokens, local proxy
   reconstruction replaces tokens with decrypted values. If run offline or if the
   cloud LLM fails, a local Answer Synthesizer generates fluent, concise, single-property
   answers directly from the knowledge graph.

3.1 DOCUMENT INGESTION FLOW (WRITE PATH: MARKDOWN & NATIVE PDF)
--------------------------------------------------------------------------------
Endpoint: POST /api/v1/documents/ingest (app/api/v1/documents.py)

Step 1: File Upload & Format Routing
- The client uploads either an OKF Markdown file (.md, .markdown, .txt) or a native
  PDF (.pdf) via HTTP multipart/form-data. Optional form-data fields (title,
  classification, department, author) allow overriding document metadata.
- If the file is a PDF:
  * PDFToOKFConverter (app/ingestion/pdf_converter.py) invokes PyMuPDF (`pymupdf.open`).
  * Extracts page text, parses PDF metadata (author, title, creation date), and computes
    a deterministic document ID: `DOC-<sha256[:12]>`.
  * Passes text to TableParser to extract and isolate tabular sections.
  * Constructs a fully validated OKFDocument with complete OKFHeader frontmatter.
- If the file is Markdown:
  * OKFParser (app/ingestion/okf_parser.py) extracts YAML frontmatter via regex.
  * SchemaRegistry validates classification levels (PUBLIC, INTERNAL, CONFIDENTIAL, RESTRICTED)
    and maps entity categories.
  * Splits body text into clean sentences while isolating tables.

Step 2: Table Isolation (Anti-Cartesian Engine)
- TableParser detects Markdown and delimited text tables.
- For each table row, it pairs the primary subject (column 1) directly with each column
  property (e.g. `subject HAS_SSN value`, `subject HAS_SALARY value`), outputting strictly
  row-scoped synthetic sentences.
- This prevents the "Cartesian explosion" bug where traditional chunking extracts relationships
  between all entities appearing in the same paragraph/table block.

Step 3: PII Detection
- For each sentence, PresidioDetectionEngine scans for configured entity categories
  (standard: PERSON, EMAIL, PHONE, US_SSN, CREDIT_CARD; custom: SALARY, PROJECT_CODE, EMPLOYEE_ID).
- If Presidio / spaCy is missing, it automatically falls back to FallbackPIIDetector.
- ConfidenceFilter removes entities below the confidence threshold (e.g., 0.85).
- Overlapping spans are resolved by picking the detection with the highest confidence score.

Step 4: Deterministic HMAC Tokenization & Vault Storage
- DeterministicTokenizer computes HMAC-SHA256(secret_key, "ENTITY_TYPE:normalized_value").
- For PERSON entities, hyphenated compound surnames (e.g., "Harold Mbeki-Sorensen") are
  normalized to their base canonical form ("harold mbeki") to ensure identity consistency
  across diverse mentions.
- Formats a unique token: ⟦XX_TYPE_NNN⟧ (e.g., ⟦E7_PERSON_001⟧).
- Replaces raw entity text in the sentence from right-to-left (preserving character indices).
- For each token, EncryptedVault encrypts the original value using AES-256-GCM with a random
  12-byte (96-bit) nonce and stores {ciphertext, nonce, entity_type, hmac_digest, doc_id}.
- If an entity is re-encountered with a more specific/longer original value (e.g., the full
  hyphenated surname), the vault automatically upgrades the stored ciphertext.

Step 5: Triple Extraction & Graph Construction
- TripleExtractor parses tokenized sentences for Subject-Predicate-Object (SVO) relationships:
  * Canonical verb mappings (MANAGES, REPORTS_TO, EARNS, LEADS, IN_DEPARTMENT, HAS_ROLE).
  * Non-token property extraction (capturing strings like "Engineering", "Q3 Merit Promotion").
  * Executive retention narrative extraction (e.g., Section 8 retention bonuses equal to "100% of base salary upon deal close").
  * Pronoun coreference resolution linking "He", "She", "They" to the previous sentence's primary subject.
  * Hub-and-spoke proximity linking (linking subject to all property tokens without creating false pairwise chains).
- KnowledgeGraphBuilder adds nodes (subjects, objects) and directed edges to a NetworkX MultiDiGraph.
- Every node and edge is tagged with document classification, allowed roles, denied roles, and namespace.

Step 6: Storage & Audit
- Document metadata is stored in state.documents dictionary.
- AuditLogger appends an immutable, SHA-256 hash-chained log entry with event type DOCUMENT_INGESTED.
- Response returns: { status: "ingested", doc_id, entities_detected, triples_extracted, tokens_stored }.

3.2 ANTI-CARTESIAN TABLE PARSING & ROW ISOLATION
--------------------------------------------------------------------------------
In unstructured RAG systems, tables are notorious for causing catastrophic graph contamination:
- In a naive system, an employee payroll table with 10 rows placed in one text chunk
  results in cross-linking employee A with employee B's salary, SSN, and manager.
- PrivaGraph solves this using TableParser (app/ingestion/table_parser.py):
  1. Header normalization: Maps column names to canonical graph predicates:
     "Salary" / "Pay" -> "HAS_SALARY"
     "SSN" / "Social Security" -> "HAS_SSN"
     "Department" / "Dept" -> "IN_DEPARTMENT"
     "Manager" / "Reports To" -> "REPORTS_TO"
     "Reason" / "Promotion" -> "HAS_REASON"
  2. Row-scoped sentence generation:
     Transforms Row 1: | Priya Nandakumar | 912-04-7731 | $210,000 | Engineering |
     Into discrete sentences:
     - "Priya Nandakumar has ssn 912-04-7731."
     - "Priya Nandakumar has salary $210,000."
     - "Priya Nandakumar is in department Engineering."
  3. Strict Isolation: TripleExtractor processes each row sentence independently,
     ensuring zero cross-row Cartesian connections are ever added to the knowledge graph.

3.3 NATURAL LANGUAGE QUERY & RETRIEVAL FLOW (READ PATH)
--------------------------------------------------------------------------------
Endpoint: POST /api/v1/query (app/api/v1/query.py)

Step 1: Query Ingestion & Query-Side Tokenization
- User submits a question: "What is Priya Nandakumar's SSN?" or "List every employee in Engineering."
- Detector scans the query itself for PII (e.g. "Priya Nandakumar" -> ⟦E7_PERSON_001⟧).
- Query tokens are stored in the vault under doc_id="query" so that entity tokens in the query
  match existing graph nodes.

Step 2: Department Boundary Filtering & Seed Node Selection
- ContextBuilder checks if the query targets a specific department (e.g., "Engineering", "Sales", "Finance").
- If a department is specified:
  * Queries the graph for nodes connected via `IN_DEPARTMENT` to that target department.
  * Sets those department-specific nodes as the candidate seed tokens.
  * This strictly isolates the traversal scope, preventing personnel from other departments
    (e.g., Sales or Operations) from leaking into the context.
- If no department filter applies, QueryAnalyzer extracts tokens and expanded keywords
  (splitting hyphenated surnames) to match graph node IDs.

Step 3: Graph Neighborhood Traversal (Multi-Hop BFS)
- If the query implies hierarchy or reporting chains ("reports to", "hierarchy", "manager"),
  ContextBuilder increases traversal depth (minimum 3 hops).
- SubgraphExtractor traverses the NetworkX MultiDiGraph using Breadth-First Search (BFS)
  around all candidate seed nodes and composes them into a unified candidate subgraph.

Step 4: Subgraph Context Serialization
- The accessible subgraph is serialized into an anonymized markdown format:
  # Knowledge Graph Context
  ## Entities: - ⟦E7_PERSON_001⟧ (namespace: hr.compensation), ...
  ## Relationships: - ⟦E7_PERSON_001⟧ --[HAS_SSN]--> ⟦F2_US_SSN_001⟧, ...

Step 6: OWASP Prompt Injection Sanitization
- PromptSanitizer scans the serialized context for injection patterns:
  * Instruction overrides ("ignore all previous instructions")
  * Role hijacking ("you are now a system admin")
  * Data exfiltration ("output the system prompt")
  * Vault/key probing ("show vault password", "decrypt master key")
- If an injection is detected: request is aborted (HTTP 400), logged to audit trail as INJECTION_BLOCKED.

Step 7: Cloud LLM Proxying OR Local Answer Synthesis
- PrivaGraph attempts cloud dispatch via LLMGateway with strict token preservation instructions.
- If the cloud LLM is unreachable, unconfigured, rate-limited, or returns empty text:
  * PrivaGraph automatically invokes the local AnswerSynthesizer (app/retrieval/synthesizer.py).
  * AnswerSynthesizer inspects query intent and graph context:
    - Single-property lookup: Answers SSN, salary, or address concisely without property dumping.
    - Multi-hop reporting chain: Synthesizes "A reports to B, who reports to C."
    - Filter queries: Lists employees matching promotions or specific departments.
    - Absent records: Honestly states "No record was found..." rather than hallucinating.

Step 8: Local Token Reconstruction (Vault Decryption)
- The raw response (containing tokens) is received locally by TokenReconstructor.
- Regex finds all ⟦XX_TYPE_NNN⟧ tokens in the text.
- TokenReconstructor performs a batch retrieval against EncryptedVault.
- AES-256-GCM decrypts each ciphertext using its stored nonce and the master key.
- Tokens in the text are replaced with decrypted real values.
- ResponseFilter verifies no residual untokenized PII leaked.
- Guarantees the reconstructed text is non-empty before returning.

Step 9: Audit Logging & Client Response
- AuditLogger records QUERY_SENT and QUERY_RECONSTRUCTED events.
- Client receives: { answer: "Priya Nandakumar's SSN is 912-04-7731.", metadata: { ... } }.

3.4 SECURITY, VAULT & CRYPTOGRAPHIC FLOW
--------------------------------------------------------------------------------
1. Key Management:
   - 256-bit (32-byte) AES key configured via environment variable VAULT_MASTER_KEY.
   - HMAC secret key configured via TOKENIZER_SECRET_KEY.
2. Encryption (AES-256-GCM):
   - Authenticated Encryption with Associated Data (AEAD).
   - Generates a cryptographically random 12-byte nonce per encryption operation.
   - Computes an authentication tag to guarantee ciphertext integrity and authenticity.
   - Value Upgrade: If an entity is re-ingested with a longer/more complete name (e.g. full
     hyphenated surname), the vault re-encrypts and upgrades the record in place.
3. Audit Log Hash Chaining:
   - Each audit entry computes SHA-256 of JSON(entry fields + prev_hash).
   - The first entry points to "GENESIS".
   - Any modification, deletion, or reordering of log entries breaks the chain and is flagged.

5. CRITICAL SECURITY & ALGORITHMIC CONCEPTS EXPLAINED
================================================================================

5.1 DETERMINISTIC HMAC TOKENIZATION & ALIAS NORMALIZATION
- Why not random UUIDs?
  If "John Smith" in Document A gets UUID_1 and "John Smith" in Document B gets
  UUID_2, the Knowledge Graph creates disconnected nodes, breaking cross-document
  reasoning. Keyed HMAC produces identical tokens for identical entities across
  documents without exposing real identities.
- Alias Normalization:
  For PERSON entities, hyphenated compound surnames (e.g. "Harold Mbeki-Sorensen"
  and "Harold Mbeki") normalize to the same base name ("harold mbeki"). This ensures
  they share the same node in the knowledge graph. When a document provides the fuller
  name, the vault automatically upgrades the stored decrypted value.

5.2 TABLE ROW ISOLATION & CARTESIAN EXPLOSION PREVENTION
- Unstructured table ingestion naively links all entities in a table together, causing
  massive false relationships (e.g., employee A linked to employee B's SSN).
- TableParser isolates each row into independent sentences with header-mapped predicates.
  TripleExtractor uses hub-and-spoke linking, linking the primary subject to its properties
  without creating pairwise cross-entity chains.

5.3 MULTI-HOP HIERARCHY TRAVERSAL & DEPARTMENT BOUNDARY FILTERING
- Department Boundary Scoping:
  When a query specifies a department (e.g., Engineering), ContextBuilder identifies
  only the nodes connected to that department via `IN_DEPARTMENT` and uses them as seed
  nodes. This prevents personnel from other departments from leaking into the context.
- Multi-Hop Traversal:
  For reporting queries, traversal depth is increased to at least 3 hops, allowing
  the system to traverse organizational chains ("Ibrahim reports to Priya, who reports to Marcus").

5.4 QUERY-AWARE ANSWER SYNTHESIS VS. RAW TRIPLE DUMPS
- Traditional fallback mechanisms dump raw graph triples:
  "- John Smith --[EARNS]--> $185,000 - John Smith --[REPORTS_TO]--> Sarah Johnson"
- PrivaGraph's AnswerSynthesizer inspects query intent:
  * Single property ("What is X's SSN?"): Returns only the SSN concisely.
  * Absent records: Honestly reports "No record was found..." rather than guessing.
  * Lists and filters: Groups results and applies predicate filters (e.g. promotions).

5.5 AES-256-GCM AUTHENTICATED ENCRYPTION
- AES-GCM is an AEAD cipher providing confidentiality and cryptographic integrity.
- Uses a unique 12-byte random nonce per encryption. Any tampering with ciphertext
  causes an `InvalidTag` exception.

5.6 CRYPTOGRAPHIC HASH-CHAINED AUDIT TRAIL
- Entry[0]: entry_hash = SHA-256(Entry[0] + "GENESIS")
- Entry[N]: entry_hash = SHA-256(Entry[N] + Entry[N-1].entry_hash)
- Any deletion or modification of prior logs breaks the cryptographic chain.

5.7 OWASP LLM TOP 10 MITIGATIONS
- LLM01 (Prompt Injection): Scanned by PromptSanitizer before prompt assembly.
- LLM02 (Sensitive Information Disclosure): Raw PII is never sent to cloud models.
- LLM06 (Excessive Agency): Scoped department boundary filtering restricts model knowledge.

5.8 DEPARTMENT BOUNDARY & ORGANIZATIONAL SCOPING
- Scopes seed entities strictly to entities matching the query's target department.

6. TOP 30 INTERVIEW QUESTIONS & MODEL ANSWERS
================================================================================

Q1: What is the core architectural innovation of PrivaGraph?
A1: PrivaGraph solves the enterprise AI dilemma by combining deterministic HMAC
    tokenization with an anonymized Knowledge Graph and a local AES-256-GCM vault.
    Instead of sending raw PII or destroying relational structure through crude redaction,
    it allows cloud LLMs to reason over relationship graphs using opaque tokens and
    reconstructs the final answer locally on-premise.

Q2: How does PrivaGraph handle native PDF documents?
A2: Through `PDFToOKFConverter` using PyMuPDF (`pymupdf`). It extracts text and tables
    across all PDF pages, derives document metadata, computes a SHA-256 document checksum,
    and synthesizes a validated OKFDocument with complete frontmatter, classification,
    and access control rules.

Q3: What is the "Cartesian explosion" problem in tabular data and how did you solve it?
A3: In standard RAG, all entities in a table row or chunk are extracted as pairwise links,
    causing O(N^2) false relationships where employee A gets linked to employee B's salary
    and SSN. We solved this with `TableParser`, which isolates each row into row-scoped
    sentences and normalizes headers into canonical predicates (`HAS_SSN`, `HAS_SALARY`).
    `TripleExtractor` then applies hub-and-spoke linking, linking the subject to its properties
    without cross-row or cross-property contamination.

Q4: Walk me through what happens when a document is ingested.
A4: (1) Ingestion: Markdown parsed by `OKFParser` or PDF converted by `PDFToOKFConverter`.
    (2) Table Isolation: `TableParser` converts tables into row-scoped sentences.
    (3) PII Detection: `PresidioDetectionEngine` detects sensitive entity spans.
    (4) Tokenization: `DeterministicTokenizer` replaces PII with tokens `⟦XX_TYPE_NNN⟧`.
    (5) Vault Storage: `EncryptedVault` stores values encrypted with AES-256-GCM.
    (6) Triple Extraction: `TripleExtractor` extracts SVO triples with coreference.
    (7) Graph Construction: `KnowledgeGraphBuilder` inserts nodes/edges into NetworkX.
    (8) Audit Logging: `AuditLogger` appends a SHA-256 hash-chained entry.

Q5: How does the query pipeline work from user input to final answer?
A5: (1) QueryAnalyzer extracts tokens and expanded keywords.
    (2) ContextBuilder checks department boundaries and sets department seed nodes.
    (3) SubgraphExtractor runs multi-hop BFS around seeds in NetworkX.
    (4) PromptSanitizer scans context for prompt injection patterns.
    (6) LLMGateway sends tokenized context + question to OpenAI/Anthropic/Gemini.
    (7) If cloud fails or is offline, local AnswerSynthesizer generates the answer.
    (8) TokenReconstructor decrypts tokens locally from EncryptedVault.
    (9) The user receives the decrypted plaintext answer.

Q6: Why did you use deterministic HMAC tokenization instead of UUIDs or hashing without a key?
A6: Plain UUIDs are non-deterministic, meaning the same person in two documents would get
    different tokens, breaking cross-document knowledge graph traversal. Simple hashing
    (like SHA-256) without a secret key is vulnerable to rainbow table and dictionary
    attacks. Keyed HMAC provides determinism for graph linking while preventing unauthorized
    reversal without the secret key.

Q7: What encryption standard is used in the vault and why?
A7: AES-256-GCM. We chose GCM because it is an AEAD cipher that provides both strong
    confidentiality and cryptographic data integrity verification via authentication tags.
    Every encryption uses a fresh 12-byte random nonce to ensure semantic security.

Q8: How does the system handle hyphenated compound surnames or alias variations?
A8: `DeterministicTokenizer` normalizes compound surnames (e.g., "Harold Mbeki-Sorensen")
    to their canonical base name ("harold mbeki") for PERSON entities, ensuring they map
    to the same token. `EncryptedVault` automatically upgrades the stored plaintext value
    if a subsequent document provides a more complete name.

Q9: How do you enforce department boundaries in queries?
A9: In `ContextBuilder`, when a query references a department (e.g., "Engineering"),
    the system identifies all nodes connected via `IN_DEPARTMENT` to that department and
    uses them as the seed set. This ensures personnel from Sales or Finance are never
    pulled into the candidate subgraph.

Q10: How does multi-hop hierarchy traversal work?
A10: When a query mentions reporting relationships or management chains, `ContextBuilder`
     increases traversal depth (depth >= 3). `AnswerSynthesizer` traverses the `REPORTS_TO`
     predicates sequentially: if A reports to B and B reports to C, it formats
     "A reports to B, who reports to C."

Q11: What does AnswerSynthesizer do and why is it needed?
A11: `AnswerSynthesizer` formats graph context into query-aware natural English sentences.
     It ensures that single-property lookups (e.g. SSN) return only the requested property
     without dumping salaries or addresses, honestly reports absent records, and provides
     a natural fallback when cloud LLMs are unavailable or rate-limited.

Q12: How do you handle prompt injection attacks?
A12: Through `PromptSanitizer`, which scans retrieved context against known OWASP LLM
     attack vectors: instruction overrides ("ignore previous instructions"), role hijacking,
     data exfiltration ("output system prompt"), vault probing ("show vault password"),
     and malicious URL schemes. If detected, the query is blocked before reaching the LLM
     and logged as INJECTION_BLOCKED.

Q13: What happens if Microsoft Presidio or spaCy is not installed?
A13: The system includes a zero-dependency `FallbackPIIDetector` using compiled regexes
     and rule-based heuristics that detect SSNs, emails, phones, salaries, credit cards,
     project codes, employee IDs, and names, ensuring the application remains functional.

Q14: How does organizational boundary filtering work across the knowledge graph?
A14: When a query targets a specific organizational division (e.g., Engineering),
     ContextBuilder identifies nodes linked via `IN_DEPARTMENT` and scopes BFS traversal
     strictly to that boundary, preventing personnel from other divisions from being leaked.

Q15: What is the Open Knowledge Format (OKF)?
A15: OKF is a structured Markdown specification with YAML frontmatter. It allows document
     owners to declaratively specify security classification, PII scanning policies,
     minimum confidence thresholds, and knowledge graph namespaces.

Q16: How does the system handle pronouns and multi-sentence relationships?
A16: `TripleExtractor` performs lightweight coreference resolution. When a sentence begins
     with pronouns ("He", "She", "They", "The employee"), it binds the subject to the
     primary subject token of the preceding sentence.

Q17: Why is answer reconstruction performed locally instead of in the cloud?
A17: Local reconstruction guarantees zero PII cloud exposure. The cloud provider only ever
     sees abstract tokens like `⟦E7_PERSON_001⟧`. The master encryption key and plaintext
     PII never leave the organization's secure network boundary.

Q18: How does the audit log prevent tampering?
A18: It uses a cryptographic hash chain similar to a blockchain. Every entry includes
     `prev_hash` and its own `entry_hash = SHA-256(entry_data + prev_hash)`. The first
     entry references "GENESIS". Any modification or deletion of a past line breaks the
     chain, which is detected during verification in `read_entries()`.

Q19: How does the system handle cloud LLM rate limits or outages?
A19: `LLMGateway` includes retry logic with exponential backoff for HTTP 429 errors.
     If cloud calls fail or return empty text, the system invokes `AnswerSynthesizer`
     to generate a high-fidelity natural answer directly from the knowledge graph context.

Q20: What is the token format and what do its components mean?
A20: Format: `⟦XX_TYPE_NNN⟧` (e.g. `⟦E7_PERSON_001⟧`).
     - `⟦...⟧`: Mathematical white square brackets (Unicode \u27e6 and \u27e7) to avoid
       collisions with standard brackets or markdown syntax.
     - `XX`: First 2 hex characters of the HMAC digest (collision namespace).
     - `TYPE`: Entity category (PERSON, SALARY, US_SSN, etc.).
     - `NNN`: Integer suffix derived from the HMAC digest.

Q21: How does the frontend visualize the knowledge graph?
A21: Using React 18 and D3.js (`d3.forceSimulation`, `d3.forceLink`, `d3.zoom`).
     Nodes are color-coded by entity type (indigo for PERSON, green for SALARY, red for SSN),
     support dragging/pinning, display directional relationship arrowheads, and show
     hover tooltips with ACL and classification metadata.

Q22: How do you prevent character offset shifting when tokenizing text?
A22: In `DeterministicTokenizer.tokenize_text()`, detected entities are sorted in descending
     order by their start offset (`sorted(entities, key=lambda e: e.start, reverse=True)`).
     Replacing tokens from the end of the string to the beginning preserves the validity
     of preceding character indices.

Q23: What OWASP LLM Top 10 vulnerabilities are addressed?
A23: LLM01 (Prompt Injection via `PromptSanitizer`), LLM02 (Sensitive Information Disclosure
     via deterministic tokenization + vault encryption + `ResponseFilter`), and LLM06
     (Excessive Agency via strict department boundary filtering).

Q24: How does the system resolve overlapping entity detections?
A24: `_resolve_overlaps()` compares overlapping character spans and selects the candidate
     with the highest confidence score, discarding lower-confidence conflicting spans.

Q25: What graph library is used and what is the production roadmap?
A25: In the MVP, NetworkX (`nx.MultiDiGraph`) provides fast in-memory graph operations.
     In Phase 2 of production, `GraphStore` will be backed by Neo4j for persistent,
     distributed graph queries with Cypher.

Q26: How does the vault handle concurrent reads and writes?
A26: In the MVP, `EncryptedVault` uses asynchronous Python dictionaries (`async def store/retrieve`).
     For enterprise deployment, it will migrate to PostgreSQL with row-level encryption or Redis.

Q27: Can you explain the Trust Zone architecture?
A27: Aligned with OWASP, we define 3 zones in `trust_boundary.py`:
     - LOCAL_TRUSTED: Inside enterprise firewall (raw PII, encryption master key, vault).
     - LOCAL_UNTRUSTED: Client browsers / incoming requests.
     - EXTERNAL_UNTRUSTED: Public cloud LLM APIs.
     `validate_flow()` enforces that raw PII never transitions to EXTERNAL_UNTRUSTED.

Q28: How do you verify graph connectivity across multiple documents?
A28: When Document A mentions "John Smith" (tokenized to `⟦E7_PERSON_001⟧`) and Document B
     mentions "John Smith", both resolve to the exact same HMAC token. In NetworkX,
     `add_triples()` adds edges to the existing node `⟦E7_PERSON_001⟧`, automatically
     forming a cross-document knowledge graph.

Q29: What automated tests are implemented in the project?
A29: A 47-test automated suite covering:
     - `test_api.py`: Full end-to-end integration (Markdown & PDF ingestion, query, audit).
     - `test_okf_parser.py`: YAML parsing, frontmatter validation, sentence splitting.
     - `test_pdf_converter.py`: PyMuPDF text & table extraction, metadata overrides, corrupt PDF handling.
     - `test_table_triples.py`: Anti-cartesian row isolation, header normalization, circuit breakers.
     - `test_tokenizer.py`: HMAC determinism, collision safety, reverse offset replacement.
     - `test_prompt_sanitizer.py`: OWASP prompt injection, role hijacking, vault probing defenses.
     - `test_query_synthesis.py`: Single-property lookups, absent record handling, list queries.
     - `test_retrieval_fixes.py`: 6 benchmark regression tests (SSN lookup, department boundaries, compound alias normalization, multi-hop reporting chains, promotion reasons, executive retention terms).
     - `test_reconstructor.py`: AES-256-GCM vault decryption and in-place replacement.

Q30: If an interviewer asks you "What would you improve if you had another month?", how do you answer?
A30: (1) Replace in-memory storage with PostgreSQL (vault) and Neo4j (graph).
     (2) Integrate Hardware Security Modules (HSM) or AWS KMS / Azure Key Vault for master key lifecycle.
     (3) Add hybrid semantic vector search + graph retrieval (GraphRAG with embeddings).
     (4) Implement OAuth2 / OIDC JWT authentication with real enterprise IdPs (Okta/Azure AD).
     (5) Add streaming token reconstruction over WebSockets / Server-Sent Events (SSE).
